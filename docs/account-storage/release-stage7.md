# Приёмка и подготовка выпуска

15 сентября 2026. Локальная приёмка ветки `codex/account-storage-foundation`.
Публикация, push и merge не входят в этот этап.

## Исправление пути обновления

Прежняя инструкция вызывала только `setup.sync`: она обновляет страницы, но не
создаёт таблицы прогресса и индексы. Для существующего сайта добавлен
`allimquran.setup.deploy`: сначала проверка ручных изменений CMS, затем импорт
шести приватных DocType и индексов, затем публикация страниц. Ошибка проверки или
схемы останавливает обновление страниц. `account_storage.install` теперь сам
загружает схемы перед созданием индексов. Повторный запуск идемпотентен.

DDL может фиксироваться отдельно от транзакции страниц. При частичном сбое
сохранить созданные таблицы, устранить причину и повторить команду; не удалять
таблицы и не восстанавливать старую БД поверх новых пользовательских данных.

## Отдельный сайт

Использован полный сайт `allim-release.localhost` с Frappe, Payments, LMS и ALLIM,
отдельными окружением Python, Redis и БД MariaDB. Рабочие сайты не изменялись.

| Компонент | Проверенная версия |
|---|---|
| Frappe | 16.33.1, `988e54f3c4c291e2077a83809663f123731abe76` |
| Payments | version-16, `cca07d9f9392e2ea0e521c5975151db9e4b6c321` |
| LMS | main, 2.63.0, `87168fc7b2f24559e474ea4702cf1aa63b0db4e8` |
| Python / MariaDB | 3.14.6 / 11.8.8 |
| Исходный ALLIM | `6a9775e064d9d22a0ba6eb224d6e7a3734347979` |

Сначала установлен прежний ALLIM, без `ALLIM Account State`. Затем созданы два
синтетических аккаунта, заявка, курс, зачисление и тестовые публичный/приватный
файлы. До обновления сделана полная резервная копия. После `setup.deploy`
сохранились 4 записи User, 1 заявка, 1 курс и 1 зачисление; второй запуск вернул
пустой `updated`.

Важное уточнение к прежним отчётам: каталог старого стенда называется
`frappe-v16-crm-develop`, но фактический импорт Frappe в нём сейчас — `17.0.0-dev`.
Название каталога не подтверждает совместимость с v16. Этот этап отдельно
проверяет заявленную v16 на закреплённом исходном коде.

На новом стенде страницы `/learn`, `/academy`, `/`, `/login` и `/lms/courses`
обрабатывает установленный Frappe. `--full-site` в тестовом сервере оставляет
только дополнительную страницу `/storage-harness` для прямых проверок SDK.
Основные страницы не подменяются HTML из файлов. Frappe и LMS собраны из своих
исходников. Для сборки на macOS использованы единые реальные пути bench/assets,
чтобы символические ссылки не включали несколько копий jQuery в один bundle.

## Проверки

Результаты сценариев и границы проверки перечислены в
[acceptance-stage7.json](acceptance-stage7.json). Исходная спецификация из 24
сценариев сохранена отдельно в [contract-scenarios.json](contract-scenarios.json).

- 139 Python-тестов: 138 прошли; один прежний пропуск требует внешнего исходного
  снимка миграции (`ALLIM_MIGRATION_SNAPSHOT`).
- 63 Node-теста, включая распознавание, проекцию, перенос и журнал.
- В Chromium и WebKit: 20 групп хранения, 7 групп переноса, 5 групп журнала;
  отдельно перезапуск процесса браузера, мобильные языки и настоящая форма входа.
- Ruff и форматирование (83 Python-файла), синтаксис 49 JS/CJS-файлов, sdist и
  wheel проходят проверку. Байт-копии модулей хранения в wheel совпали с исходниками.
- Реальные HTTP/SQL-проверки: права A/B/Guest, CSRF, запрет generic REST,
  отсутствие cookie в ответах хранения, шесть конкурентных первых открытий аккаунта, шесть доставок, конфликт,
  удаление, экспорт, принудительный SQL rollback, reset и выход.
- Браузерные сценарии запускаются с `ALLIM_TEST_BROWSER=chromium|webkit|firefox`.
  Тесты ждут фактическую смену владельца и навигацию перед следующими действиями.
  Тестовый reset не вызывается до подтверждённого входа нужного fixture-аккаунта.
- Проверка WebKit различает обработанную сетевую отмену `context/scan/pull` при навигации
  и ошибку JavaScript. `unhandledrejection` проверяется отдельно; такой сигнал
  нельзя скрыть фильтром транспортной диагностики.
- Качество микрофона не измерялось: браузерная проверка зачёта подаёт контролируемый
  результат Web Speech в настоящий текущий обработчик и matcher. Алгоритм,
  правила границ аудио и замороженный эталон не изменены.

## Воспроизведение

Нужен отдельный полный Frappe16 сайт с именем `allim-release.localhost` и двумя
fixture-пользователями `allim-storage-a@example.invalid` и
`allim-storage-b@example.invalid`. Пароли находятся только во внешнем JSON-файле
`{a:{user,password},b:{user,password}}`, права 0600. Проверки изменяют их прогресс.

```sh
FRAPPE_BENCH_ROOT=/absolute/isolated-bench ./env/bin/python \
  /absolute/allimquran/scripts/serve_account_storage_test.py \
  --sites /absolute/isolated-bench/sites --site allim-release.localhost \
  --port 18143 --full-site

ALLIM_PLAYWRIGHT=/absolute/node_modules/playwright \
ALLIM_TEST_CREDENTIALS=/private/fixture-credentials.json \
ALLIM_TEST_URL=http://127.0.0.1:18143 ALLIM_TEST_BROWSER=chromium \
node scripts/check_account_storage_browser.cjs
```

Аналогично запускаются `check_account_import_browser.cjs`,
`check_account_journal_browser.cjs` и `check_account_release_browser.cjs`.
Последний закрывает процесс браузера, повторно открывает тот же профиль,
проверяет мобильные EN/RU/AR, настоящую форму входа и монтирование LMS.
Проверки на общих аккаунтах разделены минутными окнами: ограничения приложения
60 POST и 120 GET в минуту не ослаблялись.

`check_account_storage_paging.py` проверяет вставку перед курсором scan,
удаление/редакцию во время чтения, догоняющий pull и реальную очистку индекса
старше 90 дней. Браузер отдельно получает однократный `cursor_expired` и проверяет
сохранность очереди при повторной загрузке.

`check_account_storage_volume.py` создаёт 5 000 валидированных событий и 5 000
записей журнала через тот же серверный Service. Это подготовка данных напрямую
в отдельной БД, а не замер пропускной способности HTTP-записи.
`check_account_volume_browser.cjs` затем измеряет настоящие paged API,
IndexedDB, проекцию и открытие/сохранение в интерфейсе.

`rehearse_account_storage_release.py` делает полную копию с файлами, проверяет
защиту от изменений CMS, возвращает прежние страницы через guarded sync и снова
применяет текущий выпуск. Сравниваются хэши строк всех шести таблиц прогресса,
пользователей, заявки, курса и зачисления. Серверный API при откате страниц
остаётся доступен; схемы и новые записи сохраняются.

## Большая история и восстановление

Проверены 10 002 записи: 5 000 событий, 5 000 записей журнала, цикл и цель.
Оба браузера получили 51 страницу API; совпали 5 000 занятий, объём 5 000 страниц
с повторами и покрытие одной уникальной страницы. В списке отрисовано 30 строк.

Это единичные замеры на macOS с локальной сетью, без эмуляции слабого телефона
или задержки мобильной сети. Хранилище пока читает полный снимок; особенно в
WebKit это заметная часть времени сохранения. Проверка 10 002 записей не задаёт
гарантированный предел истории и не подтверждает нагрузку множества аккаунтов.

Полные копии до/после находятся вне Git в `/tmp/allim-stage7-backups` (приватные
каталоги и файлы). После проверки большой истории выполнен откат трёх страниц
к `6a9775e` и повторный deploy; хэши всех защищённых таблиц совпали.
Копия после обновления восстановлена в отдельный сайт
`allim-release-restore.localhost`, БД `allim_release_restore_20260915`.
Повторно совпали хэши всех шести таблиц прогресса, User, заявки, курса,
зачисления и содержимое публичного/приватного тестовых файлов. Ключ шифрования
восстановлен из приватной копии конфигурации. Восстановленный сайт также прошёл
настоящий HTTP-вход, CSRF/open и чтение первой страницы приватной истории.

Логи: `/tmp/allim-stage7-{site,python-paging,python-volume,rehearsal,restore}.log`,
`/tmp/allim-stage7-{chromium,webkit}-{storage,import,journal,release,volume}.log`.
Снимки мобильных экранов: `/tmp/allim-release-{chromium,webkit}-{en,ru,ar}.png`.
Метрики и соответствие контракту сохранены в Git в `acceptance-stage7.json`.
Резервные копии, пароли и содержимое приватных БД в Git не добавлялись.

## Перед публикацией

На целевом сервере проверить фактические версии Frappe/LMS, дрейф CMS, полную
резервную копию и доступность её восстановления, права приватных файлов,
исключение приватных API из кеша прокси/CDN и реальный HTTPS-вход. Локальный
Werkzeug не подтверждает эти свойства production-инфраструктуры.

Проверка WebKit на macOS не заменяет физический iPhone/iPad. Firefox в этом
окружении не запускается даже с пустым профилем (`Could not find profile folder`);
его совместимость не подтверждена. До публикации остаётся проверка Firefox в
рабочем окружении и Safari/iOS на устройстве, включая сохранение между запусками.

Для отката интерфейса заранее сохранить прежние страницы и текущие API/схемы.
Провести его в согласованном окне обслуживания: прежний клиент не умеет
автоматически отправлять новые локальные действия в аккаунт. Возврат полной
старой БД не является штатным откатом интерфейса.
