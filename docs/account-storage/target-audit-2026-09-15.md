## Изменения CMS: блокирующее расхождение

Правило действующего preflight применено к исходникам кандидата и живым записям.
Конфликтуют HTML, CSS и JavaScript двух страниц:

- `/`: новые языки TG/UZ/TT, переработанный выбор языка, оформление и блоки
  пути обучения, приглашений и реферальной программы; дополнительные шрифты.
- `/learn`: выбор методик `foundation300`, `linked33`, `turkishWall33`,
  `mauritanianLawh`, рекомендации по истории попыток, библиотека Ляуха,
  переработанный выбор языка и изменения обработчиков чтения.

Это не только оформление. Появились `memorizationMethod`, `hifzCoach`, новые
разделы `heartMushaf` и отдельная IndexedDB `allim-lawh-library-v1`. Они не входят
в прежнюю карту переноса. Текущий контракт отдельно исключал новые методики
и фото Ляуха из первого выпуска. После обнаружения их на живом сайте нельзя
просто заменить страницы кандидатом и считать весь существующий прогресс
поддержанным. Нужно отдельно согласовать сохранение этих функций, обновить
инвентаризацию данных и проверить переход гостя/аккаунта для принятого состава.

Есть возврат адресов `/files/allim-*` вместо Git-ресурсов `/assets/allimquran/*`.
Нужно сохранить исходный снимок CMS и дополнительные медиа, затем совместить
изменения с новым хранением через обычный guard из [deployment.md](../deployment.md).
Сброс отпечатков или обход preflight уничтожит защиту от перезаписи этих правок.

HTML/JS сравнивались с установленным `6a9775e`. Например, JavaScript главной:
2 971 → 4 146 строк; `/learn`: 7 821 → 9 126 строк. Хэши шести полей сохранены
в JSON. Исходный публичный код и подробные diff сохранены только локально
в `/tmp/allim-target-audit-20260915.json` и `/tmp/allim-target-*.diff`.
Согласование и перенос правок в данном аудите не выполнялись.

## HTTPS, прокси и приватность

- `/`, `/learn`, `/academy`, форма входа с возвратом в Learn и `/lms/courses`
  отвечают HTTP 200. Сертификат проверен штатным TLS-клиентом, действует до
  1 декабря 2026; соединение TLS 1.3. HTTP перенаправляется на HTTPS в nginx.
- Cookie `sid` на проверенных гостевых ответах имеет Secure, HttpOnly и
  SameSite=Lax. Страница входа и ответ приватного Frappe API гостю содержат
  `no-store`; API гостю возвращает 403.
- `ignore_csrf` не включён. Ключ шифрования сайта присутствует; значения ключей,
  cookie и паролей в отчёт не включались.
- В загруженной конфигурации nginx не найдено proxy/fastcgi cache и удаления
  Cache-Control. Маршруты нового API попадут в Frappe, а не в ASR-прокси.
  Серверный DNS указывает на origin; в HTTP нет признаков промежуточного кеша.
  Это наблюдение текущего пути, не аудит неизвестной панели внешнего CDN.
- `/protected/` имеет `internal`. Проверены прямой `/private/backups/...` и
  `/protected/private/backups/...` для существующей копии конфигурации: оба 404.
  Проверка реального приватного вложения невозможна без fixture: их в File нет.
- Новый account API ещё не установлен. Его authenticated no-store,
  cookie-neutral ответы и изоляцию A/B/Guest через production HTTPS нужно
  проверить после согласованной установки. Вход под реальным аккаунтом
  в данном аудите не выполнялся; загрузка формы его не заменяет.

## Резервные копии и права

В штатном каталоге найдена полная копия от 7 сентября, 17:54 по имени файла:
БД ~24,4 МБ, публичный архив ~29,2 МБ (24 файла), приватный архив пустой.
Более поздняя копия 18:35 содержит БД ~24,9 МБ и конфигурацию без пары архивов
файлов того же запуска. Оба gzip полностью прочитаны с проверкой целостности;
оба tar открываются. Это проверка контейнеров, а не фактического восстановления.
Команда `bench` и Python-реализация `restore` доступны. Восстановление этой
production-копии в отдельный сайт ещё не проведено. Локальная репетиция этапа 7
проверяла только синтетический стенд.

`site_config.json` имеет режим 0664, файлы штатных backup — 0644,
каталоги private/backups — 0775. Все родительские каталоги доступны для прохода.
Проверка `test -r` от системного пользователя `nobody` подтверждает возможность
прочитать конфигурацию и дамп БД; их содержимое этой проверкой не читалось.
При этом HTTP-доступ закрыт. Приватные каталоги `/var/backups/allimquran/*`
имеют 0700, но не заменяют свежий полный backup сайта.

Перед выпуском нужны права, ограничивающие чтение конфигурации/копий владельцем,
с учётом работающего backup-процесса; свежая полная копия БД, public/private files
и ключа шифрования; сохранённые исходники CMS и проверка восстановления в
изолированном окружении. Права и расписание копирования здесь не менялись.

## Следующий порядок

1. Согласовать обнаруженные изменения CMS и новые типы локальных данных;
   перенести принятые изменения в Git, сохранив источник и медиа.
2. Повторить приёмку объединённого кандидата на версиях целевого сервера,
   затем браузерные проверки и проверку физического iOS.
3. Перед согласованным выпуском устранить локальные права чтения, сделать
   свежий полный backup, проверить восстановление и повторить preflight.

Push, merge, публикация и исправления production этим аудитом не выполнялись.
