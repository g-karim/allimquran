# CSRF при первом входе и одновременном открытии вкладок

17 октября 2026. Ветка `codex/account-storage-foundation`, база изменения `62e4f5b`.
Исправлен дефект из [сентябрьского браузерного аудита](browser-audit-2026-09-15.md).
Изменение и проверки выполнены локально; production не обновлялся.

## Причина и исправление

До изменения исходный HTTP-тест снова воспроизвёл ошибку: шесть первых GET
`context` одной новой сессии вернули шесть разных CSRF-токенов. Из следующих
шести POST `open` пять получили HTTP 400 / `CSRFTokenError`, один — HTTP 200.
Причина — ленивое создание токена в `frappe.sessions.get_csrf_token()`:
несколько запросов успевали загрузить сессию без токена и затем перезаписывали её.

Добавлен app-owned `allimquran.session_security.before_request`. Он выполняется
после штатной HTTP-аутентификации/проверки CSRF и до обработки страниц и API.
При успешном входе токен сохраняется до отправки ответа login. Это также защищает
нативные страницы Frappe/LMS, которые сами вызывают `get_csrf_token`.
`on_session_creation` здесь не подходит: он выполняется до проверки CSRF самого
login POST, и создание токена в нём отклонило бы этот вход.

Для существующей сессии без токена:

1. Строка `Sessions` блокируется через `SELECT … FOR UPDATE` и перечитывается
   из БД. Повторный `frappe.cache.hget` не подходит: он возвращает уже загруженную
   копию из локального кэша запроса.
2. В текущем объекте сессии заменяется весь снимок, включая `last_updated`.
   Это не даёт отложенному `Session.update` записать прежнюю копию без токена.
3. Штатный генератор Frappe сохраняет один случайный токен. Ожидающие запросы
   используют сохранённое значение. Восемь ограниченных попыток с откатом
   транзакции обрабатывают конфликты MariaDB при конкурентном перечитывании.

Гости и сессии с готовым токеном проходят без дополнительной блокировки/записи.
Удалённая сессия или несовпадение её владельца завершаются отказом; сессия
не создаётся заново. Генерация и её штатный commit происходят до прикладных
изменений текущего запроса. Код Frappe не изменён; повторной отправки операций
с ослабленной проверкой CSRF нет.

## Проверки

Стенд: отдельный `allim-youth.localhost`, БД `allim_youth_20261017`,
Frappe 16.26.3, MariaDB 11.8.8, Payments, полная LMS 2.45.2
(`0cd844e212e9818feacdbcdfd44677f7504dea28`) и ALLIM из рабочей ветки.
Синтетические аккаунты: `allim-storage-a/b@example.invalid`.

`scripts/check_account_session_start.py` теперь проверяет и шесть параллельных
POST `open`, одного владельца/аккаунт и строгий отказ на пустой/неверный токен.
Проверены свежий вход и моделирование старой сессии без токена, включая два
отдельных серверных процесса на портах 18643/18644. В каждом случае: один токен,
одна привязка сессии, один аккаунт, шесть успешных открытий. Приватные ответы
сохраняют `no-store` и не возвращают `Set-Cookie`. Неверный и отсутствующий
токены получают штатный HTTP 400 / `CSRFTokenError`.

`scripts/check_account_session_browser.cjs` запускает три группы по шесть вкладок
в каждом движке. В группах минимального harness первые запросы `context`
удерживаются до прибытия всех шести, затем направляются на настоящий сервер.
Шесть полных страниц reader запускаются одновременно без искусственной задержки
их сетевых таймаутов. Предварительного запроса для прогрева нет;
ответы приватных API не подменяются.

| Движок, Playwright 1.62.1 | Итог |
|---|---|
| Chromium / Chrome 155.0.8059.84 | 5 групп, 18 вкладок прошли |
| WebKit 26.5 | 5 групп, 18 вкладок прошли |
| Firefox 153.0 | 5 групп, 18 вкладок прошли |

Проверены одновременная готовность всех вкладок, шесть независимых изменений
с подтверждением сервера и пустой очередью, восстановление в шести нативных
страницах `/learn` другого чистого профиля, отдельные токены разных сессий,
отказ на токен другой сессии и изоляция второго пользователя. Необработанных
JS-ошибок и неуспешных приватных запросов вкладок в успешных прогонах нет.
При плотном последовательном запуске всех наборов с теми же двумя аккаунтами
сработал штатный лимит 60 записывающих запросов в минуту (429); повтор после
смены окна прошёл. Лимиты не отключались.

Дополнительно:

- Полный набор хранения Firefox: все 20 групп прошли, включая прежний сбой
  одновременного первого открытия, offline, выход/смену владельца, поздний ответ,
  reset и истечение сессии. Ожидание владельца в тесте проверяет разрешённый

- Настоящая форма входа Frappe в Chrome, возврат в reader, перезапуск браузера,
  гостевое хранение, мобильные EN/RU/AR и открытие LMS: четыре группы прошли.
- Python: 152 теста, 151 прошёл, один прежний opt-in пропущен. Шесть новых
  тестов охватывают актуальный/устаревший снимок, генерацию, откат/повтор,
  ограничение попыток и отказ для исчезнувшей/чужой сессии.
- Node: 72 теста прошли. Ruff, форматирование, синтаксис 38 прикладных/встроенных
  JS-скриптов и изменённых браузерных скриптов, sdist/wheel прошли.
- Все 164 записи трёх ранее импортированных курсов сохранили исходный полный
  хэш; три курса остаются черновиками.

## Повторение

На подготовленном изолированном сайте, с его runtime и `PYTHONPATH`:

```sh
python scripts/check_account_session_start.py \
  --url http://127.0.0.1:18643 --peer-url http://127.0.0.1:18644 \
  --credentials /private/csrf-credentials.json

python scripts/check_account_session_start.py \
  --url http://127.0.0.1:18643 --peer-url http://127.0.0.1:18644 \
  --credentials /private/csrf-credentials.json \
  --legacy-site allim-youth.localhost --sites /absolute/fixture/bench/sites

ALLIM_PLAYWRIGHT=/absolute/node_modules/playwright \
ALLIM_TEST_BROWSER=firefox \
ALLIM_TEST_URL=http://127.0.0.1:18643 \
ALLIM_TEST_CREDENTIALS=/private/csrf-credentials.json \
node scripts/check_account_session_browser.cjs
```

`--peer-url` необязателен; два процесса должны обслуживать один тестовый сайт.
Legacy-режим убирает токен только из только что созданной сессии указанного
синтетического пользователя. Скрипты принимают только HTTP loopback и имена
выделенных аккаунтов; пароли, cookie, токены и привязки в отчёты не выводятся.
Firefox на этой macOS требует отдельных пустых `MOZ_APP_DATA` и
`MOZ_LOCAL_APP_DATA`, как в сентябрьском аудите. Наборы следует запускать
с учётом штатного ограничения запросов на одного пользователя.

Локальные логи и обезличенные отчёты: `/tmp/allim-youth-20261017/csrf-*`.
Этот стенд не содержит сервисы ASR/перевода/мусхафа; они не входят в проверку
инициализации аккаунта. Физический Safari/iOS, согласование production CMS и
условия резервного копирования остаются отдельными условиями выпуска.
При будущем развёртывании потребуется перезапуск web workers и обновление
кэша hooks сайта; изменения таблиц или содержимого страниц для этого исправления
не требуются.
