Реализован локально 14 сентября 2026 в `codex/account-storage-foundation`, после контракта `d57f191`. Серверный слой проверен на отдельном Frappe 16 сайте `allim-storage.localhost` с MariaDB 11.8.8. Подключение браузерных страниц — этап 4; производственный сайт не изменялся.

## Состав

- [account_storage.py](../../allimquran/account_storage.py): context/open, apply, scan/pull, приватный экспорт, подтверждённый reset и условный logout через существующую сессию Frappe. Владелец проверяется сервером, CSRF обязателен для POST, ответы не кэшируются.
- [storage/validation.py](../../allimquran/storage/validation.py): допустимые поля и типы, даты/зоны, ограничения размера, ссылки на Коран, события, заметки, планы, настройки и исходные агрегаты.
- [storage/service.py](../../allimquran/storage/service.py): устойчивые квитанции, проверка версии, tombstones, варианты конфликтов, явное разрешение и повторяемый импорт отдельных элементов.
- [storage/repository.py](../../allimquran/storage/repository.py): приватные DocType, уникальные индексы и блокировка Account State. Первое создание дополнительно блокирует существующую строку User.
- [storage/projection.py](../../allimquran/storage/projection.py): итоги и действующий хифз 300× из исходных агрегатов и уникальных событий, с определённым порядком и календарными интервалами.

Добавлены шесть DocType: Account State, Progress Record, Operation, Change, Reset и Export. У них нет разрешений обычных ролей, импорта или истории DocType Version. Удаление User через Frappe удаляет связанные данные в той же транзакции. Переименование User сохраняет постоянный account_id через стандартное обновление Link.

Справочник [account-storage-catalogue.json](../../allimquran/public/data/account-storage-catalogue.json) содержит только позиции слов и страницы: 6236 аятов, 77124 слова, все 604 страницы, около 348 KiB. ## Уточнения контракта при реализации

1. Для начального открытия `context` авторизованного пользователя возвращает CSRF-токен стандартного Frappe и привязку сессии. Они нужны клиенту в памяти, не входят в прогресс/очередь/экспорт. GET-параметры account/epoch/session принимаются только заголовками, чтобы привязка не оказывалась в URL.
2. Пользовательский value ограничен 60 KiB: оставлен запас в пределах 64 KiB записи для серверной оболочки конфликта. Ответы scan/pull дополнительно ограничены по байтам, cursor не пропускает отброшенные из страницы записи.
3. MariaDB snapshot isolation может прервать даже ожидающее блокирующее чтение, если другой запрос успел commit. Внутренние чтения при записи используют текущую блокирующую версию; обработчик повторяет целую откатившуюся транзакцию до восьми раз с короткой случайной задержкой. После исчерпания попыток возвращается повторяемый storage_busy. ID операций сохраняются.
4. Удаление/reset блокируют доступ к старым экспортам немедленно. Физические временные файлы удаляет плановая очистка; рабочие записи, tombstones и квитанции не подчиняются сроку хранения индекса изменений. Резервные копии сайта относятся к будущей приёмке выпуска.
5. Событие связной страницы допускает доставку до события её начала. Оно сохраняется как факт, а проекция засчитывает закрепление только при наличии подходящего начала и завершённого хифза аятов к моменту события.

[check_account_storage_site.py](../../scripts/check_account_storage_site.py) выполнен через настоящий HTTP/Frappe, cookie-сессии и MariaDB. Проверены:

- шесть одновременных повторов одной операции — одна запись/версия;
- два пользователя, Guest, запрещённый generic REST и CSRF;
- частичная ожидаемая ошибка пачки с отдельной квитанцией;
- обе версии конфликта, его разрешение и запрет воскрешения удалённого;
- приватная выгрузка и её инвалидирование после изменения;
- реальная SQL-ошибка триггером после INSERT записи: вся транзакция откатилась, повтор после снятия триггера применился один раз;
